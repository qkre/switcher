# 스위처 — 아이폰 직접 연결 페이지

`index.html` 한 장짜리 정적 페이지입니다. 폰이 스위처에 **직접** BLE 로 붙습니다.
PC 도, 웹 서버도 필요 없습니다.

## GitHub Pages 로 올리기

1. 이 프로젝트를 GitHub 저장소에 올립니다 (`docs/` 폴더 포함).
2. 저장소 **Settings > Pages** 로 갑니다.
3. **Source** 를 `Deploy from a branch`, **Branch** 를 `main` / `/docs` 로 지정하고 저장.
4. 1~2분 뒤 `https://<사용자명>.github.io/<저장소이름>/` 이 열립니다.

## 아이폰에서 쓰기

iOS 사파리와 크롬은 Web Bluetooth 를 지원하지 않습니다. 반드시 아래 브라우저가 필요합니다.

1. App Store 에서 **Bluefy – Web BLE Browser** 를 설치합니다.
2. Bluefy 에서 위 https 주소를 엽니다.
3. **연결하기** → 목록에서 `SWITCHER_M` 선택.
4. ON/OFF 를 누릅니다.

`http://` 나 `file://` 로는 동작하지 않습니다 (Web Bluetooth 는 보안 컨텍스트 필수).

## 값의 출처

`android/flutter_app/lib/main.dart` 및 `pyswitcherio` 와 동일합니다.

| | 값 |
|---|---|
| 서비스 UUID | `0000150b-0000-1000-8000-00805f9b34fb` |
| 캐릭터리스틱 UUID | `000015ba-0000-1000-8000-00805f9b34fb` |
| 1구 ON / OFF | `0x00` / `0x01` |
| 2구 ON / OFF | `0x05` / `0x03` |

## 안 되는 것

- **시리 명령** — 단축어는 BLE GATT 쓰기를 할 수 없습니다.
- **예약** — 페이지가 닫히면 실행되지 않습니다.

둘 다 필요하면 PC 의 `web_server.py` 를 함께 쓰세요. 단, 스위처는 BLE 연결을
하나만 받으므로 폰과 PC 가 동시에 연결하면 서로 뺏습니다.

## 시리 / 단축어 (시험적)

단축어 앱에는 BLE 명령 액션이 없습니다. 대신 주소에 명령을 실어 Bluefy 로 열면
페이지가 뜨자마자 알아서 전송합니다.

    https://<주소>/?do=1:on      스위치1 켜기
    https://<주소>/?do=1:off     스위치1 끄기
    https://<주소>/?do=2:on      스위치2 켜기
    https://<주소>/?do=2:off     스위치2 끄기
    https://<주소>/?do=all:on    둘 다 켜기
    https://<주소>/?do=all:off   둘 다 끄기

단축어 구성: [URL] 액션에 위 주소 -> [URL 열기] 액션. 이름을 "불 꺼" 처럼 지으면
시리가 그 이름을 알아듣습니다.

되는지 여부는 Bluefy 가 `navigator.bluetooth.getDevices()` 를 지원하는지에 달려 있습니다.
페이지 맨 아래 "설정" 카드에 지원 여부가 표시됩니다.

  * 지원함  -> 기기 선택창 없이 자동 전송. 시리로 쓸 수 있습니다.
  * 미지원 -> 열 때마다 기기를 손으로 골라야 해서 시리로는 못 씁니다.

어느 쪽이든 Bluefy 앱이 화면에 뜨는 것 자체는 막을 수 없습니다.
완전히 손 안 대는 시리 제어는 PC 의 web_server.py 방식만 가능합니다.

## 배터리 잔량

스위처가 표준 BLE 배터리 서비스(`0000180f`)를 제공하는 경우에만 "배터리" 카드가
나타나고 잔량을 보여줍니다. 알림(notify)을 지원하면 값이 바뀔 때 자동으로 갱신되고,
아니면 "새로고침"으로 다시 읽습니다.

제공하지 않는 기기라면 카드가 아예 나타나지 않습니다. 그 경우 "설정" 카드의
"기기 정보" 줄에 `배터리 서비스(180f) 없음` 이라고 표시됩니다.

배터리를 읽으려면 requestDevice 때 권한을 받아둬야 하므로,
이 기능을 추가한 뒤에는 **연결하기를 다시 눌러 기기를 한 번 더 선택**해야 합니다.

### 표준 배터리 서비스가 없는 기기

이 스위처는 `180f` 를 제공하지 않는다(확인됨). 대신 스위처 서비스 `150b` 안에
characteristic 이 2개 있고, 우리가 쓰는 건 명령용 `15ba` 하나뿐이다.
나머지 하나에 상태/잔량이 들어있을 수 있어서 진단 기능을 넣었다.

"설정" 카드에 연결 후 표시되는 것:

    스위처 서비스(150b) 내부: 15ba [write](명령용)  |  15bb [read,notify] -> 4a 01 00

읽기 가능한 characteristic 은 원시 바이트를 16진수로 보여준다.
"알림 관찰 시작" 을 누르면 notify 로 흘러오는 값을 실시간으로 보여준다
(스위치를 눌렀을 때 값이 바뀌는지 확인용).

진단은 읽기만 한다. 알 수 없는 characteristic 에 쓰기는 절대 하지 않는다.

### 이 스위처의 실제 구성 (확인됨)

    150b (스위처 서비스)
      15ba  [write, writeWithoutResponse]           명령용
      ????  [read, write, writeWithoutResponse]     읽으면 1바이트

    180f (표준 배터리 서비스)  없음
    notify 지원                없음

배터리 잔량을 알려주는 수단이 이 기기에는 없다.

두 번째 characteristic 을 읽으면 1바이트가 나오는데, 관측된 값 `01` 은
1구 OFF 명령 바이트와 같다. 마지막 명령 또는 현재 상태를 담고 있을 가능성이 있다.
"지금 값 다시 읽기" 로 스위치를 켜고 끈 전후를 비교하면 확인할 수 있다.

    00 = 1구 ON    01 = 1구 OFF
    05 = 2구 ON    03 = 2구 OFF

값이 명령에 따라 바뀌면 현재 상태 표시에 쓸 수 있다.
바뀌지 않으면 다른 용도이므로 건드리지 않는다.

### 결론 (실기기 확인)

두 번째 characteristic 의 값은 스위치를 켜고 끈 전후로 **바뀌지 않았다**.
따라서 현재 상태 표시에도 쓸 수 없다.

이 스위처에서 얻을 수 있는 정보는 없다. 명령을 보내는 것만 가능하다.
진단 UI 는 평소 화면에서 감췄고, 필요할 때만 주소에 `?debug=1` 을 붙여 본다.

## 연결 자동화

Web Bluetooth 는 기기 선택창(`requestDevice`)을 "사용자가 누른 직후"에만 열 수 있다.
페이지 로드만으로 선택창을 띄우는 것은 명세상 불가능하다. 그래서 이렇게 한다.

1. 브라우저가 `getDevices()` 를 지원하면
   - 로드 직후 기억된 기기에 자동으로 붙는다 (탭 0번)
2. 지원하지 않으면
   - ON/OFF 버튼 자체가 연결을 겸한다. 한 번 누르면
     선택창 -> 연결 -> 명령 전송이 한 번에 끝난다 (탭 1번 + 기기 선택)
   - 이후 같은 세션에서는 선택창 없이 바로 전송된다

"연결하기" 버튼은 미리 붙여두고 싶을 때만 쓰면 된다.

## 오류 메시지

Bluefy 는 표준 DOMException 대신 숫자 코드만 던지는 경우가 있다(관측: `2`).
그래서 어느 단계에서 실패했는지 함께 표시한다.

    실패(기기 선택): ...   requestDevice 단계
    실패(연결): ...        gatt.connect / 서비스 조회 단계
    실패(전송): ...        write 단계

원인을 못 알아보는 오류는 종류와 원문을 그대로 보여준다 (`Error: 2`).

## 기억된 기기에 자동 연결이 실패할 때

Bluefy 는 `getDevices()` 를 지원한다(기기를 기억한다). 그런데 돌려준 기기에
`gatt.connect()` 를 해도 붙지 못하고 숫자 `2` 를 던지는 경우가 있다.
"권한이 있다"는 것과 "지금 붙을 수 있다"는 것은 다르기 때문이다.

이때 그 기기 객체를 계속 붙들고 있으면 `requestDevice` 를 건너뛰게 되어
기기 선택창이 영영 뜨지 않는다. 그래서 한 번도 연결에 성공하지 못한 기기는
실패 즉시 버리고, 다음에 버튼을 누르면 선택창이 다시 뜨도록 한다.

### 자동 연결 절차

1. 기억된 기기에 바로 `gatt.connect()` — 실패하면 0.6초 뒤 한 번 더
2. 그래도 안 되면 `watchAdvertisements()` 로 기기가 다시 보일 때까지 최대 12초 대기,
   광고가 잡히면 그때 연결
3. 그래도 실패하면 기기를 놓아주고 수동 선택으로 넘긴다

브라우저가 `watchAdvertisements` 를 지원하지 않으면 2단계는 건너뛴다.
지원 여부는 `?debug=1` 의 진단줄에서 볼 수 있다.
